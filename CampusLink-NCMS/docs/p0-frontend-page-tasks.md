# P0 前端页面任务单

## 一、目标

为 `teacher-web` 明确 P0 直接编码任务，确保前端可以围绕总览、学生、设备、监控四条主线快速交付。

## 二、页面清单

### 1. 登录页

目标：提供基础登录入口与后续鉴权占位。

任务：

- 实现登录表单布局
- 预留账号、密码输入框
- 预留登录提交逻辑与错误提示区域
- 登录成功后跳转仪表盘

### 2. 仪表盘

目标：展示系统总览信息。

任务：

- 展示学生总数
- 展示已注册设备数
- 展示在线设备数
- 展示离线设备数
- 展示模式分布统计

依赖接口：

- `GET /api/dashboard/overview`

### 3. 学生列表页

目标：维护学生基础信息。

任务：

- 展示学生表格
- 支持关键字搜索
- 支持新增学生弹窗
- 支持编辑学生弹窗
- 支持状态展示

依赖接口：

- `GET /api/students`
- `POST /api/students`
- `PUT /api/students/:id`

### 4. 设备列表页

目标：查看设备注册状态与基础信息。

任务：

- 展示设备表格
- 支持在线状态筛选
- 支持模式筛选
- 支持查看设备详情侧栏或弹窗
- 支持触发模式切换操作

依赖接口：

- `GET /api/devices`
- `GET /api/devices/:id`
- `POST /api/devices/:id/mode`

### 5. 监控总览页

目标：集中查看在线设备状态。

任务：

- 展示在线设备列表
- 显示最后心跳时间
- 显示当前模式
- 预留实时刷新能力

依赖接口：

- `GET /api/monitor/online-devices`

## 三、公共组件任务

### 布局组件

- 顶部导航栏
- 侧边菜单栏
- 主内容容器

### 业务组件

- 数据统计卡片
- 学生表格
- 设备表格
- 模式切换弹窗
- 通用分页组件

## 四、状态管理任务

- 建立用户登录态 store
- 建立仪表盘数据 store
- 建立学生列表 store
- 建立设备列表 store
- 建立监控列表 store

## 五、路由任务

- `/login`
- `/dashboard`
- `/students`
- `/devices`
- `/monitor`

## 六、接口封装任务

- `api/system.ts`
- `api/dashboard.ts`
- `api/students.ts`
- `api/devices.ts`
- `api/monitor.ts`

## 七、页面开发顺序

1. 先完成基础布局与路由
2. 完成仪表盘
3. 完成学生列表页
4. 完成设备列表页
5. 完成监控总览页
6. 最后补齐模式切换弹窗与统一错误提示

## 八、验收标准

- 前端路由可正常切换
- 仪表盘可渲染总览数据
- 学生页可完成新增和编辑
- 设备页可查看详情并触发模式切换
- 监控页可展示在线设备与最后心跳时间
