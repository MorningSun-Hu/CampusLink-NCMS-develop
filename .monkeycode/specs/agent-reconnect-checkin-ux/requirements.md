# Requirements Document

## Introduction

本次需求修复学生机离线行为、签到输入与授课身份校验，并调整教师端班级/学生管理入口。目标是：学生机在教师机不可达时保持运行并恢复上次模式；开放模式签到可输入中文；授课模式必须用学号+密码签到；批量重置密码放到学生管理；班级管理不再承担模式切换。

涉及范围：`student-agent`（`agent-core`、`campus-checkin`、`campus-lock`、`campus-guard`）、`teacher-server`、`teacher-web`。

## Glossary

- **学生机**：教室里运行 `student.exe` 的设备终端。
- **教师机**：运行 `teacher.exe` 的管理端。
- **上次状态**：学生机本地加密配置中保存的 `current_mode`。
- **初始状态**：学生机从未成功保存过模式，或配置中无有效 `current_mode`。
- **课程已结束**：教师端该设备（或其所属班级）当前生效模式已从 `teaching` 离开。
- **开放模式签到**：`open` 模式下仅登记使用者姓名的签到。
- **授课模式签到**：`teaching` 模式下必须用学号与签到密码完成的签到。
- **系统快捷键屏蔽**：拦截 Win、Alt+Tab、Ctrl+Esc、Ctrl+Alt+Delete 等离开签到/锁屏界面的组合键。

## Requirements

### Requirement 1: 学生机持续连接教师机

**User Story:** AS 机房管理员, I want 学生机在连不上教师机时继续运行并重试, so that 教室设备不会因为教师机晚开而退出。

#### Acceptance Criteria

1. WHEN 学生机启动后连接教师机失败, 学生机 SHALL 保持进程运行并继续尝试连接。
2. WHILE 学生机与教师机断开, 学生机 SHALL 按退避间隔持续重试发现与连接，重试次数无上限。
3. IF WebSocket 心跳或命令通道断开, 学生机 SHALL 继续按退避间隔重连，并在重连成功后恢复心跳。
4. WHILE `campus-guard` 守护 `student.exe`, 守护进程 SHALL 在 `student.exe` 意外退出后再次拉起该进程。

### Requirement 2: 启动时恢复上次模式

**User Story:** AS 学生, I want 开机后先进入上次教室状态, so that 我不必等教师机连上才知道当前能否使用电脑。

#### Acceptance Criteria

1. WHEN 学生机启动且本地存在有效上次状态, 学生机 SHALL 立即进入该上次状态对应的界面与策略。
2. WHEN 学生机启动且处于初始状态, 学生机 SHALL 进入开放模式。
3. WHEN 学生机启动且上次状态为授课模式，并且从教师机取得的最新状态表明课程已结束, 学生机 SHALL 进入锁定模式。
4. WHEN 学生机启动且上次状态为授课模式，并且尚未从教师机取得最新状态, 学生机 SHALL 先按授课模式界面与策略运行，同时持续尝试连接教师机。
5. WHEN 学生机成功连上教师机，并且本地上次状态为授课模式，并且该设备在教师机上的当前模式已不是 `teaching`, 学生机 SHALL 进入锁定模式，并将本地上次状态保存为 `locked`。
6. WHEN 学生机成功连上教师机，并且不满足「上次授课且课程已结束」条件, 学生机 SHALL 采用教师机下发的当前模式覆盖本地上次状态，并保存为新的上次状态。
7. WHEN 学生机采用锁定模式或教师机下发的模式, 学生机 SHALL 按该模式执行签到、锁屏或桌面策略。

### Requirement 3: 开放模式签到支持中文输入法

**User Story:** AS 学生, I want 开放模式签到时用中文输入姓名, so that 我能正确登记使用者。

#### Acceptance Criteria

1. WHILE 开放模式签到界面显示使用者姓名输入框, 签到程序 SHALL 允许系统中文输入法向该输入框提交汉字。
2. WHILE 签到或锁屏界面运行, 签到/锁屏程序 SHALL 继续拦截 Win、Alt+Tab、Alt+Esc、Alt+F4、Ctrl+Esc、Ctrl+Alt+Delete 等系统快捷键。
3. WHILE 开放模式签到界面的使用者姓名输入框获得焦点, 签到程序 SHALL 允许单独按下 Shift 键（供输入法切换或临时英文），并自动调起中文输入法。
4. WHEN 签到程序启动, 签到程序 SHALL 保持当前线程的 IME 可用。

### Requirement 4: 批量重置密码入口调整

**User Story:** AS 教师, I want 在学生管理里按班级批量重置签到密码, so that 密码管理与学生名单在同一处完成。

#### Acceptance Criteria

1. WHEN 教师打开学生管理页, 教师端 SHALL 提供批量重置密码入口。
2. WHEN 教师在学生管理页发起批量重置密码, 教师端 SHALL 要求教师选择一个班级，并将该班级全部学生的签到密码重置为初始密码。
3. WHEN 教师打开班级管理页, 教师端 SHALL 在班级详情中隐藏批量重置密码按钮。
4. WHEN 批量重置完成, 系统 SHALL 把受影响学生标记为下次签到需修改密码，并写入可追溯操作日志。

### Requirement 5: 授课模式按学号校验签到

**User Story:** AS 教师, I want 授课模式必须用学号和密码签到, so that 他人无法用随意姓名进入桌面。

#### Acceptance Criteria

1. WHILE 设备处于授课模式, 签到界面 SHALL 提示学生输入学号与签到密码，输入框文案为学号。
2. WHEN 学生在授课模式提交签到, 系统 SHALL 仅按学号精确匹配学生记录，并校验签到密码。
3. IF 授课模式提交的学号不存在，或签到密码不匹配, 系统 SHALL 拒绝签到并保持签到界面。
4. IF 授课模式请求未携带已通过学号+密码校验的学生标识, 系统 SHALL 拒绝该次签到。
5. WHEN 学生使用学号与正确密码完成授课模式签到, 系统 SHALL 继续校验该学生座位号与当前设备座位号一致，一致后允许进入桌面。

### Requirement 6: 班级管理移除模式切换

**User Story:** AS 教师, I want 班级管理只维护班级、学生机和座位, so that 模式切换只在设备监控等专用入口进行。

#### Acceptance Criteria

1. WHEN 教师打开班级管理详情, 教师端 SHALL 隐藏模式切换按钮与「模式切换」分区。
2. WHILE 教师使用班级管理页, 教师端 SHALL 继续提供班级的学生、学生机、座位号维护能力。

## 已确认决策

1. 学生机连接失败后进程保持运行，重试次数无上限；守护进程在学生主进程退出后继续拉起。
2. 启动时先恢复本地上次模式；无上次模式则开放模式；上次为授课且教师机确认课程已结束则锁定。
3. 开放模式签到保留系统快捷键屏蔽，放开 Shift 与 IME，并在姓名框焦点时自动调起中文输入法。
4. 授课模式签到只接受学号，不再用姓名匹配学生。
5. 批量重置密码只出现在学生管理；班级管理去掉模式切换入口。
6. 「课程已结束」判定：该学生机在教师机上的当前模式已不是 `teaching`。
7. 上次为授课且课程已结束时进入锁定模式，即使教师机当前为开放或考试。
8. 学生管理批量重置密码使用页面当前班级筛选；未筛选时先提示选择班级。
